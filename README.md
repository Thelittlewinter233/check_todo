# 每日打卡 check_todo

一款「真监督」的自律打卡 Android 应用：打卡、待办、课表、提醒、桌面小卡片，外加 **AI 拍照判定**（把打卡照片发给大模型判断你是否真的完成了任务）与 **AI 自律周报**。纯 Java、零第三方库，2638 项 JVM 单元测试全程护航。

> 项目前身是移动端 PWA（Vite + Vue 3 + Capacitor），现以 Android 原生实现为主形态，Web 版仍保留在 `src/` 可独立构建运行。

## 功能

### 打卡任务
- 多任务管理：名称、每周重复日多选、每日打卡时间窗、完成所需时长；
- 状态机：`未开始 / 可打卡 / 已完成 / 已错过`，时间窗内才能打卡、当天不可重复打卡；
- 连续天数（streak）：只按重复日统计，错过即归零，**不提供补签**——自律不打折；
- 打卡日历与请假：按月视图查看/补记历史，支持请假日（不计漏卡）；
- 紧急度排序：截止 − 所需，快到期的任务自动置顶；
- 提醒：打卡截止前自动本地通知（含电池优化引导）。

### 待办
- 起止时间 + 花费时长，完成即从列表消失；
- 同样可开启 AI 拍照判定（见下）。

### 课表
- 教务系统 CSV / HTML 导入解析（离线解析，无账号上传）。

### 桌面小卡片
- 打卡任务与待办直接在桌面操作：打卡、完成、取消打卡；
- AI 判定条目点击后回到 App 走拍照链路；
- 世代校验防跨实例误点。

### AI 拍照判定（BYOK，可选）
- **建任务/待办时可选「AI 拍照判定」**：拍一张标准照 + 写下打卡特征描述（如"桌面收拾干净"）；
- 之后每次打卡/完成需要拍照（**拍照或相册上传均可**）：
  1. **L1 离线预检**（零网络）：EXIF 拍摄时间新鲜度（拦截旧图）+ aHash 感知哈希去重（拦截重复交图）；相册渠道自动跳过新鲜度校验、保留去重；
  2. **L2 模型判定**：标准照 + 当前照 + 特征描述发给视觉模型，返回 `pass / fail / uncertain` 与理由，提示词注入防护内置；
  3. **三分支落地**：通过 → 完成；不通过 → 展示理由可重拍或申诉；不确定 → 完成并标记「待复核」；
- **三模型失败转移链**：按序最多尝试 3 个模型（默认 GLM-4.1V-Thinking-Flash → GLM-4V-Flash → glm-4.6v-flash，全为免费视觉模型）；429/网络/不支持图片自动换下一个，401/403（key 无效）直接降级；
- **max_tokens 自适应**：不同模型输出上限不同（16K/96K…），服务端拒绝时解析上限自动降额重试；
- **永不阻塞**：未配 key、断网、额度耗尽 → 自动降级为「本地预检 + 待复核」，打卡流程照常走完。

### AI 自律周报（BYOK，可选）
- 每周一 00:00 自动生成上一自然周报告：每任务应打卡/实际完成/连续天数/漏卡清单 + 待办完成情况 → 总结 + ≤3 条具体到任务名的警醒；
- 手动入口：⋮ → 「AI 周报」可随时查看历史（保留 8 份）或生成本周报告；
- 周报专用文本模型 GLM-4-Flash-250414（16K 输出），失败自动落到判定链模型。

### 主题
- 浅色 / 深色 / 跟随系统。

## 技术特点

- **纯 Java、零第三方库**：不依赖 AndroidX / Retrofit / OkHttp / 图片库，全部基于框架 API（`HttpURLConnection`、`org.json`、系统相机 intent 等）；
- **分层**：`domain/` 纯 Java 值对象与决策逻辑（JVM 直测，不依赖 Android）+ 薄壳层（Activity / Widget / 通知）；
- **TDD**：2638 项 JVM 单元测试（打卡状态机、待办、课表解析、提醒调度、卡片路由、AI 判定链、周报），构建脚本强制全绿才能产出 APK；
- **持久化**：本地 SharedPreferences JSON（`check-todo.v1` / `ai-verify.v1` / `weekly-report.v1`），无账号、无云端、无遥测。

## 环境要求

- Windows + JDK 11+（构建脚本用 `--release 11`）；
- Android SDK 构建工具（`aapt2`、`d8`、`apksigner`、`zipalign`），并在 `build.bat` 顶部按你的 SDK 路径核对变量；
- Web 版另需 Node.js + npm。

## 构建

### Android（主形态）

```bat
cd native-android
build.bat
```

脚本依次执行：aapt2 编译链接 → javac → d8 → 打包对齐 → apksigner 签名 → 全量 JVM 测试 → 签名校验。全部通过（`EXIT=0`）后产出 `native-android/out/checktodo-debug.apk`，直接安装即可。

### Web PWA 版

```bash
npm install
npm run dev      # 开发：http://localhost:5173/
npm run build    # 产物 dist/
npm test
```

## 使用说明

1. 安装 APK 后从底部切换 **打卡 / 待办 / 课表** 三个页签；
2. 「新建任务」设置重复日与时间窗；「新建待办」设置起止时间；
3. 打卡页点圆区即完成打卡（今天可打卡的任务会高亮）；
4. 添加桌面小卡片（系统小组件菜单）可在桌面直接打卡/完成；
5. 课表页导入教务 CSV/HTML 文件即可离线解析。

### 开启 AI 判定与周报（约 2 分钟）

1. 到 [智谱开放平台](https://open.bigmodel.cn/) 注册并在「API keys」页创建一个 key（有永久免费视觉模型，个人打卡频率零成本）；
2. App 主界面 ⋮ → **AI 判定设置** → 粘贴 API key（默认已预置智谱网关与三模型链）→ 可点「测试连接」验证；
3. 建任务/待办时勾选 **「AI 拍照判定」**，拍标准照（或从相册选择）+ 写一句特征描述；
4. 之后打卡/完成时拍照或选相册图，等待判定结果即可；
5. ⋮ → **AI 周报**：可手动生成本周报告；每周一 00:00 也会自动生成上周报告并通知。

### AI 判定设置项

| 设置 | 说明 |
|---|---|
| base_url | OpenAI 兼容网关；填到 `/v4` 或直接粘贴完整 `chat/completions` 地址均可 |
| 判定模型 1/2/3 | 失败转移链，按序尝试；留空跳过该位；建议全用视觉模型 |
| API key | 只存本机 SharedPreferences，不写入任何任务数据或备份 |

## 课表导入教程

课表支持三种导入方式，入口都在 **课表页**。导入后进入预览，勾选确认后才写入课程表，可随时手动编辑。

### 方式一：教务系统在线导入（推荐，无需电脑）

1. 课表页点「导入」→ 选择「教务系统导入」；
2. 输入学校教务系统网址（http/https 开头），在内嵌浏览器里**登录你自己的教务账号**（账号密码只在你与教务系统之间，App 不保存、不上传）；
3. 登录后手动翻到**课表页面**：
   - 一般系统会自动识别页面上的课表网格；
   - 新版正方（jwglxt）等 POST 型系统：先在教务里点一次「查询」按钮，再点 App 的「提取课表」；
   - 页面结构特殊时可点「框架」勾选目标区域后「提取选中框架」；
4. 提取成功 → 预览课程列表 → 确认导入。

内置多类教务页面解析器：**正方、金智、URP 新版、金智 Kingosoft、Element-UI** 等，覆盖大多数高校。

> 排查：导入失败时可在诊断面板点「复制诊断」，内容不含账号密码，可发给开发者协助。

### 方式二：HTML 文件导入（电脑配合，适合在线导入失败时）

1. 在电脑浏览器登录教务系统，打开**课表页面**；
2. `Ctrl + S` 保存网页，类型选「**仅 HTML**」（不要选"全部"或"mhtml"）；
3. 把 HTML 文件发到手机（微信/QQ/数据线均可）；
4. 课表页 →「导入」→「HTML 文件」→ 选中该文件 → 预览 → 导入。

解析器会从所有表格中启发式定位课表主网格，自动拆分单双周与多段周次。

### 方式三：CSV 文件导入（表格整理，最可控)

用 Excel / WPS 按以下 7 列整理（**有表头或无表头都支持**，逗号 / 分号 / Tab 分隔均可）：

```csv
课程名,星期,开始节,结束节,老师,教室,周次
高等数学,周一,1,2,张老师,A101,1-16
大学英语,周三,3,4,李老师,B202,1-8,10-18
```

- 星期：周一～周日（也接受数字 1-7）；
- 周次：`1-16` 区间、`1-8,10-18` 多段、单周数字均可；
- 整理后「另存为 CSV」→ 手机 → 课表页 →「导入」→「CSV 文件」→ 预览 → 导入。

## 获取 API Key 并开启 AI 功能（分步教程）

AI 判定与 AI 周报使用 **BYOK（Bring Your Own Key）** 模式：你注册模型服务商、创建自己的 key、填进 App——额度、费用、数据都由你自己掌控。默认预置智谱开放平台（有永久免费视觉模型，个人打卡频率零成本）。

### 第一步：创建你自己的 API Key

1. 打开 [智谱开放平台](https://open.bigmodel.cn/)，手机号注册并登录；
2. 右上角进入「控制台」；
3. 左侧菜单找到 **「API keys」**（或"账户设置 → API keys"）；
4. 点「创建 API Key」，随意命名（如 `check_todo`）；
5. 复制生成的 key（形如 `xxxxxxxx.xxxxxxxx`，一串点号分隔的字符）。

> ⚠️ **key 等同于你的账户密码**：不要发到聊天群、不要截图外传、不要提交到任何代码仓库。泄露后请立即回控制台删除重建。

### 第二步：在 App 里配置

主界面右上角 **⋮ →「AI 判定设置」**，三个字段：

| 字段 | 怎么填 |
|---|---|
| base_url | 保持默认 `https://open.bigmodel.cn/api/paas/v4/`（用智谱就不用改）；也兼容粘贴完整 `chat/completions` 地址，或填任意 OpenAI 兼容网关 |
| 判定模型 1 / 2 / 3 | 失败转移链，从上到下依次尝试。默认 `glm-4.1v-thinking-flash` → `glm-4v-flash` → `glm-4.6v-flash`（都是免费视觉模型）。某格留空 = 跳过该位 |
| API key | 粘贴第一步复制的 key。**只存本机**，不会出现在任务数据、备份或日志里 |

填完点 **「测试连接」**——约几秒内应显示 `✔ 连接成功：<模型名>`。测试通过后，建任务/待办时就能勾选「AI 拍照判定」了。

### 第三步：模型怎么选（都是免费的）

| 模型 | 类型 | 适用 |
|---|---|---|
| `glm-4.1v-thinking-flash` | 视觉（带推理） | 判定质量最好，推荐链首；生成较慢 |
| `glm-4v-flash` | 视觉 | 快，质量稳定 |
| `glm-4.6v-flash` | 视觉 | 视觉模型备选 |
| `glm-4-flash-250414` | **纯文本**（周报专用，已内置） | 只处理文字，16K 输出 |

> 注意：**判定链（模型 1/2/3）必须放"视觉"模型**——它们要看打卡照片；纯文本模型收到图片会被自动跳过。周报是纯文本任务，App 已内置 `glm-4-flash-250414`，无需配置。

### 常见问题

| 现象 | 原因与处理 |
|---|---|
| `✔ 连接成功` | 配置完成，直接用 |
| `✘ HTTP 429（1305 访问量过大）` | 免费模型高峰期限流——App 会自动换链中下一个模型；都繁忙时稍后再试 |
| `✘ HTTP 401/403` | key 错误或已失效 → 回控制台重新生成 |
| `✘ 网络超时` | 已内置 90 秒超时 + 失败自动换模型；仍失败说明网络到服务商不通，检查代理/网络 |
| 打卡显示「待复核」 | 判定没拿到明确结论（未配 key / 网络失败 / 模型不确定），打卡已完成，不影响使用 |
| 判定理由带 `[模型名]` 前缀 | 表示该次判定实际由哪个模型做出，转移链生效的痕迹 |

## 隐私与安全

- 无账号体系、无云端、无遥测，所有数据只在本机；
- 开启 AI 判定后，打卡照片与特征描述会发送到你自行配置的模型服务商用于判定——该行为在设置页有明示，且 AI 判定为任务级可选；
- API key 只存本机，代码中不存在任何内置密钥；
- 判定历史（时间/结论/置信度/理由/是否申诉）随打卡记录持久化，可审计。
